# Issue #20: Dice semantic profile and independent oracle

This directory is private verification infrastructure. It is outside both
publishable packages and is not a runtime API.

The immutable Dice semantic identity is:

```text
dice-v1/utf16-bounded-left-to-right-1
```

It is deliberately distinct from the package version, the PRNG schema version,
and the PRNG Sequence Profile
`xoshiro128ss-1.1/direct128-msb-rejection-1`. A change to grammar, UTF-16
offsets, parsing, evaluation order, arithmetic, state consumption, failure
selection, or any result value requires a new Dice identity and reviewed old
and new vectors.

`oracle.mjs` independently implements the bounded scanner, complete parser,
full-AST analyzer, and signed depth-first evaluator. It composes sampling only
through the public exports of the issue-17 runtime oracle. It imports no
package, source, declaration, or future implementation module.

The v1 resource envelope is literal and inclusive at its limit:

| Dimension | Limit |
| --- | ---: |
| source UTF-16 code units | 64 |
| numeric-token decimal digits | 3 |
| parenthesis nesting depth | 4 |
| AST nodes | 15 |
| dice terms | 4 |
| completed Die Samples | 8 |
| supported die sides | 100 |
| absolute arithmetic magnitude | 100 |
| minimum evaluation steps | 24 |
| per-sample rejection attempts | 4 |

Static diagnostics select the earliest UTF-16 source offset. At a tied static
resource offset the order is AST nodes, dice terms, Die Samples, supported
sides, arithmetic magnitude, and evaluation steps. Static failures consume no
state. Sampling exhaustion and dynamic resource failures retain the completed
Roll Trace and actual successor Generator State; an incomplete sample is not
added to the trace.

The literal corpus contains representative successes, all grammar productions,
all supported whitespace code points, rejected Unicode whitespace, UTF-16
offset cases, every public failure family, precedence collisions, each limit at
the limit and one beyond, post-consumption failures, a forced rejection path,
and a literal side grid for every side count from 1 through 100. Expected
totals, traces, states, and sample-attempt paths are committed data rather than
values generated by the checker.

Run the blocking gate from the repository root:

```sh
node verification/issue-20/check.mjs
```

Pass a candidate corpus as the first argument, or set
`DRDICE_DICE_GOLDEN_FILE`, to audit a proposed change without replacing the
committed file. Any oracle/golden disagreement fails. The checker also pins
the semantic identity, limits, tie-break order, canonical states, side grid,
and the import/package boundary.
