PRNG type API prototype

A small, inspectable state machine for the proposed Seed → Generator State → raw step → bounded sample boundary. Every operation returns a value plus an explicit successor state, or a structured failure.

Throwaway decision artifact. This is a non-cryptographic model for games, tests, and type-system experimentation. It does not publish a package and it never asks the browser for entropy.

Issue #9 question: What is the smallest rough type-level API artifact that makes initialization, stepping, bounded sampling, explicit state threading, invalid states, failures, and the runtime-oracle relationship concrete enough to accept or revise?

Sequence profile and type-level proposal

xoshiro128ss-1.1/direct128-msb-rejection-1

The profile freezes the generator, direct four-word initialization, high-bit rejection, and attempt-fuel behavior.

type Seed = { kind: "Seed"; words: [Word32, Word32, Word32, Word32] }
type GeneratorState = { kind: "GeneratorState"; words: [Word32, Word32, Word32, Word32] }
type Initialize<SeedWords> = Success<GeneratorState> | InvalidSeedFailure
type Next<S> = Success<{ word: Word32; state: GeneratorState }> | InvalidStateFailure
type Sample<S, Bound, MaximumAttempts> =
  | Success<{ value: number; state: GeneratorState; attempts: number }>
  | InvalidStateFailure
  | InvalidBoundFailure
  | InvalidAttemptFuelFailure
  | SamplingAttemptsExhausted<{ maximumAttempts: number; attempts: number; state: GeneratorState }>

Boundaries this prototype keeps visible

        
    
          
  • Sequence profile: xoshiro128ss-1.1/direct128-msb-rejection-1 identifies every value-changing choice.
    • 
          
  • Replay Token: profile + schema version + canonical Seed; it restarts from the beginning.
    • 
          
  • Serialized Generator State: profile + schema version + complete current State; it resumes at the next word.
    • 
          
  • Runtime oracle: the pure model below is a separate number-based mirror of the fixed-width type-level operations; the golden output/state is a literal review fixture, not generated from TypeScript types at runtime.
    • 
          
  • Failure state: exhaustion returns consumed attempts and successor State; preflight failures return no consumed State.
