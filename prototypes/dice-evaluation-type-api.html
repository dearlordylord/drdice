Dice Evaluation type API · logic prototype

Issue #10 question

What rough type-level API and diagnostic artifact makes valid Dice Evaluations, Roll Traces, successor states, parse failures, resource-limit failures, and composition with the PRNG package concrete enough for a human to accept or revise?

This is a throwaway planning artifact. The page is a pure in-memory model around an intentionally thin DOM shell; the TypeScript file carries the literal aliases and an independent internal oracle. The public type evaluator intentionally materializes a bounded literal corpus; arbitrary-source execution and production checker support remain #11 implementation work.

Proposed public shape

type Initialize<SeedWords> =
  | { ok: true; value: GeneratorState }
  | { ok: false; code: "invalid-seed-shape" | "invalid-seed-word" | "invalid-seed-zero" };

type Evaluate<Source, GeneratorState, MaximumAttempts>
  = { ok: true; value: {
      total: number; rollTrace: DieSample[]; successorState: GeneratorState
    }}
  | { ok: false; code: "expected-expression" | "expected-die-sides" | "expected-closing-parenthesis" | "leading-zero" | "unexpected-token" | "dice-count-zero" | "side-count-zero" | "resource-limit-exceeded" }
  | { ok: false; code: "invalid-state-shape" | "invalid-state-word" | "invalid-state-zero" | "invalid-attempt-fuel"; details: { partialTrace: DieSample[]; successorState: GeneratorState | null } }
  | { ok: false; code: "sampling-attempts-exhausted"; details: { attempts: number; partialTrace: DieSample[]; successorState: GeneratorState } };

type DieSample = { sideCount: number; face: number };
type Sample<GeneratorState, SideCount, MaximumAttempts>
  = { ok: true; value: { value: number; state: GeneratorState; attempts: number } }
  | { ok: false; code: "invalid-state-shape" | "invalid-state-word" | "invalid-state-zero" }
  | { ok: false; code: "invalid-bound" | "invalid-attempt-fuel" }
  | { ok: false; code: "sampling-attempts-exhausted"; details: { attempts: number; state: GeneratorState } };
// Evaluate composes Sample once per Die Sample; it does not duplicate PRNG logic.
type MaterializedHappy = {
  ok: true; value: {
    total: 5;
    rollTrace: [{ sideCount: 6; face: 1 }, { sideCount: 6; face: 1 }];
    successorState: GeneratorState<["00003007", "00000405", "00000405", "01800000"]>;
  }
};
type MaterializedExhaustion = {
  ok: false; code: "sampling-attempts-exhausted"; details: {
    attempts: 1; partialTrace: [{ sideCount: 6; face: 1 }];
    successorState: GeneratorState<["ffffffff", "00000000", "000001ff", "ffffffff"]>;
  }
};
type MaterializedInvalidState = {
  ok: false; code: "invalid-state-word";
  details: { partialTrace: []; successorState: null }
};
type MaterializedInvalidFuel = {
  ok: false; code: "invalid-attempt-fuel";
  details: { partialTrace: []; successorState: GeneratorState }
};

Successful Dice Evaluations have exactly total, rollTrace, and successorState. A failure has no total. Sampling exhaustion includes the exact attempts, completed partial trace, and advanced state. Pre-consumption syntax/domain/static-resource diagnostics omit partialTrace/successorState; the caller retains unchanged input. State/fuel failures and post-consumption failures carry explicit state and trace.

The HTML model owns no DOM access. The TypeScript file's oracleEvaluate is an independent runtime correctness oracle; neither implementation is a production package or a parity gate.

Diagnostic contract visible in this sketch

Preflight is deterministic and first-diagnostic-wins: source length → scanning/parsing → full-AST domain validation → static resource preflight → Generator State and fuel validation → depth-first, left-to-right evaluation. Supported-side checks belong to static resources only after the complete domain traversal. Within static resources, the earliest source offset wins; ties use ast-node-count → dice-term-count → die-sample-count → supported-side-count → arithmetic-magnitude → evaluation-steps. Constant-only subexpressions are checked before any sample. Source offsets are zero-based UTF-16 code-unit offsets in the original source; EOF is source.length. ASCII space, tab, LF, and CR are the only whitespace.
